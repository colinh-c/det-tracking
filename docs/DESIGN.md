# November 7 DET launch stack design

This implements Colin's previously described and confirmed three-module architecture. All image detection, slower phase estimation, prediction and control computation runs on the Mac. Existing Pi capture, encoder transport and SKR Pico stepping are reused through an explicit gateway. This is authorized software development and testing; no hardware actuation or deployment occurs during development.

Before main, prioritize correct-rocket retention with narrow tracking and wide acquisition. During descent maximize time on the correct target; under main aim at estimated rocket COM. First flight has no payload release; future parachute-center handoff remains disabled. Nominal field geometry is 500 m, flat, with editable bearings and rail settings. Synthetic truth is isolated from the algorithm observations. Camera calibration and motor/encoder registration are required before live automatic operation. Manual jog is unchanged.

The implementation choice is Python 3.9+, NumPy and OpenCV, isolated in this new directory. Messages are timestamped on Mac monotonic time. Frame acquisition age uses gateway metadata plus transport timing, never directly compares Pi and Mac clocks. ENU and true-North-clockwise bearing are explicit. Image rays and boresight transforms share one projection model.

The fast perception module uses intensity, motion and temporal association on both cameras, reports uncertain identity and loss, and estimates body COM only from justified orientation/CG data. The slower phase module combines observed angle/rate and apparent canopy features with a labeled prior; prior timing is not claimed as a visual classification. The predictor combines the saved OpenRocket angular trajectory with measured angular innovations and rates to extrapolate to actuation time. The executor uses measured encoder pose and velocity feedforward with bounded configured motor speed/acceleration, stale-data stop and manual override.

The runtime supports synthetic closed-loop simulation, recorded replay and live Pi HTTP capture. Default is simulation or dry run. The local display has dual images, target overlays, acquisition click, phase/source, launch clock, geometry/calibration status, manual override and stop. Live motion is a separate explicit CLI choice with final calibration prerequisites. No arbitrary new mechanical travel limits are introduced. New Pi velocity gateway owns the serial device exclusively and expires commands on lease timeout.

Verification covers geometry and angle wrapping; cross-camera association and distractors; missed/stale/duplicate frames; phase uncertainty and manual main override; latency lead and encoder freshness; saturation and stale command rejection; real HTTP integration and watch-dog behavior; complete synthetic flight and main-only trials. Metrics distinguish synthetic truth visibility from detector retention, phase source and actual pointing error. No real-flight success claim is made from synthetic tests.
